## 方法與限制

- 基準：開始工作時乾淨的 `104aa3b250829d827d7a1900402415ad9937c3eb`，先建置並保存原版 dist，再修改程式。
- 瀏覽器：本機 Edge 153.0.4234.48，Playwright headless。
- 網路：Chrome DevTools Protocol 模擬 150 ms 延遲、1.6 Mbps 下載、0.75 Mbps 上傳；CPU 放慢 4 倍。
- 每輪使用新的瀏覽器 context，禁用 HTTP 快取及 Service Worker；修改前後同一台電腦、同一份量測腳本及本機 HTTP 伺服器。先完成基準三輪，再完成新版三輪。
- 手機為 390 × 844 視窗，桌機為 1280 × 900；這是桌機瀏覽器模擬視窗及限速，並非實機手機。
- 本機靜態伺服器使用 no-store，沒有 gzip/Brotli；原版的 Google Fonts 使用當時的真實外部服務。因此數字不代表 GitHub Pages/CDN 或真實使用者的絕對秒數，也不涵蓋重訪快取情境。
- FCP、LCP 記錄最終語系頁的 Performance Entry，加上入口到最終頁的時間。字型就緒為 load 後等待 `document.fonts.ready` 的採樣時間；載入完成後再等 750 ms 擷取 LCP。傳輸量加總這段期間完成請求的 CDP encodedDataLength，包含回應標頭；不是只加總原始檔案大小，也不包含截圖時才觸發的遠端 lazy 圖片。
- 原始數據及截圖在本機 `performance-results/`（Git 忽略）。本報告保留部署前的本機量測摘要，不是正式站測量。

重跑方式（需先保留修改前後各自的 build 快照）：

```powershell
$env:CHROMIUM_PATH='C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
node scripts/measure-load.mjs performance-results/before before 3
node scripts/measure-load.mjs performance-results/after after 3
```
